SECTION 1: RECOMMENDATION ENGINE ANALYSIS
-------------------------------------------

The recommendation engine experienced degraded performance due to increased model complexity. The team deployed a new collaborative filtering model (v3.2) that requires 40% more memory per inference.

Root Cause Analysis:

```python
# Before: Simple matrix factorization (v2.8)
def get_recommendations(user_id, n=10):
    user_vector = embeddings.get(user_id)  # 128-dim
    scores = np.dot(item_matrix, user_vector)
    return np.argsort(scores)[-n:]

# After: Hybrid model with attention (v3.2)
def get_recommendations(user_id, n=10, context=None):
    user_vector = embeddings.get(user_id)  # 512-dim
    context_vector = context_encoder(context)  # 256-dim
    combined = attention_layer(user_vector, context_vector)

    # Multi-stage retrieval
    candidates = ann_index.search(combined, k=100)
    scores = reranker.score(combined, candidates)

    # Business rule filtering
    filtered = apply_business_rules(scores, user_id)
    return filtered[:n]
```

Memory Allocation Changes:

+------------------+----------+----------+----------+
| Component        | v2.8     | v3.2     | Change   |
+------------------+----------+----------+----------+
| Model weights    | 2.1 GB   | 3.8 GB   | +81%     |
| Embedding cache  | 512 MB   | 1.2 GB   | +134%    |
| Inference buffer | 256 MB   | 512 MB   | +100%    |
| Total per inst.  | 2.9 GB   | 5.5 GB   | +90%     |
+------------------+----------+----------+----------+

Lambda Configuration Impact:
- Previous: 3008 MB memory, ~800ms cold start
- Current: 5120 MB memory, ~2100ms cold start
- Provisioned concurrency increased from 50 to 100 instances

SECTION 2: DATABASE MIGRATION RESULTS
---------------------------------------

The DynamoDB to Aurora PostgreSQL migration for user-preferences completed in three phases:

Phase 1 - Dual Write (July 1-15):
All writes duplicated to both DynamoDB and Aurora. Read traffic remained on DynamoDB. Zero downtime achieved. Data consistency verified hourly using checksums.

Phase 2 - Shadow Read (July 15-31):
Read traffic served from DynamoDB with shadow reads to Aurora. Latency comparison:

```sql
-- Optimized query for user preferences retrieval
SELECT
    p.user_id,
    p.preference_key,
    p.preference_value,
    p.updated_at,
    COALESCE(p.metadata->>'source', 'direct') as source
FROM user_preferences p
WHERE p.user_id = $1
    AND p.is_active = true
    AND p.updated_at > NOW() - INTERVAL '90 days'
ORDER BY p.updated_at DESC;

-- Index supporting the query
CREATE INDEX CONCURRENTLY idx_prefs_user_active
ON user_preferences (user_id, is_active, updated_at DESC)
WHERE is_active = true;
```

Phase 3 - Cutover (August 1):
Traffic switched to Aurora with DynamoDB as fallback. Monitoring confirmed:
- p50 latency: 45ms -> 3ms (93% improvement)
- p99 latency: 120ms -> 12ms (90% improvement)
- Cost reduction: $4,200/month -> $890/month (79% savings)

SECTION 3: INCIDENT REPORT - AUGUST 23 OUTAGE
-----------------------------------------------

Duration: 47 minutes (14:23 - 15:10 UTC)
Severity: SEV-2
Impact: Payment processing unavailable for 12% of users

Timeline:
- 14:23 UTC: CloudWatch alarm triggered for payment gateway error rate >1%
- 14:25 UTC: On-call engineer paged, began investigation
- 14:28 UTC: Identified root cause: expired TLS certificate on internal mTLS connection between payment-gateway and fraud-detection service
- 14:35 UTC: Certificate rotation initiated
- 14:42 UTC: New certificate deployed to 3/5 AZs
- 14:55 UTC: Deployment to remaining AZs delayed due to deployment pipeline timeout
- 15:02 UTC: Manual deployment to remaining AZs
- 15:10 UTC: Full service restored, error rate returned to baseline

Post-Incident Actions:
1. [COMPLETED] Add certificate expiry monitoring with 30-day advance warning
2. [COMPLETED] Implement automatic certificate rotation via ACM
3. [IN-PROGRESS] Add deployment pipeline timeout alerting
4. [PLANNED] Conduct chaos engineering exercise for certificate failures

Financial Impact:
- Estimated lost transactions: $142,000
- Customer credits issued: $8,500
- Engineering time: 12 person-hours (~$3,600)
